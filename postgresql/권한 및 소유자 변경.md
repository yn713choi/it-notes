# PostgreSQL 권한 및 소유자 변경

## 1. 테이블 소유자 변경
```sql
-- 단일 테이블 소유자 변경
ALTER TABLE table_name OWNER TO new_owner;

-- 스키마의 모든 테이블 소유자 변경
REASSIGN OWNED BY old_owner TO new_owner;

-- 특정 스키마의 모든 테이블 소유자 변경
DO $$
DECLARE
    r record;
BEGIN
    FOR r IN SELECT tablename FROM pg_tables WHERE schemaname = 'schema_name'
    LOOP
        EXECUTE 'ALTER TABLE schema_name.' || quote_ident(r.tablename) || ' OWNER TO new_owner';
    END LOOP;
END $$;
```

## 2. 인덱스 소유자 변경
```sql
-- 단일 인덱스 소유자 변경
ALTER INDEX index_name OWNER TO new_owner;

-- 특정 스키마의 모든 인덱스 소유자 변경
DO $$
DECLARE
    r record;
BEGIN
    FOR r IN SELECT indexname FROM pg_indexes WHERE schemaname = 'schema_name'
    LOOP
        EXECUTE 'ALTER INDEX schema_name.' || quote_ident(r.indexname) || ' OWNER TO new_owner';
    END LOOP;
END $$;
```

## 3. 테이블 권한 관리

### 3.1. 권한 부여 (GRANT)
```sql
-- 특정 테이블에 대한 모든 권한 부여
GRANT ALL PRIVILEGES ON table_name TO user_name;

-- 특정 권한만 부여
GRANT SELECT, INSERT, UPDATE ON table_name TO user_name;

-- 스키마의 모든 테이블에 대한 권한 부여
GRANT ALL PRIVILEGES ON ALL TABLES IN SCHEMA schema_name TO user_name;

-- 향후 생성될 테이블에 대한 권한 설정
ALTER DEFAULT PRIVILEGES IN SCHEMA schema_name
GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO user_name;
```

### 3.2. 권한 회수 (REVOKE)
```sql
-- 특정 테이블의 모든 권한 회수
REVOKE ALL PRIVILEGES ON table_name FROM user_name;

-- 특정 권한만 회수
REVOKE INSERT, UPDATE ON table_name FROM user_name;

-- 스키마의 모든 테이블 권한 회수
REVOKE ALL PRIVILEGES ON ALL TABLES IN SCHEMA schema_name FROM user_name;
```

## 4. 권한 확인

### 4.1. 테이블 권한 확인
```sql
-- 특정 테이블의 권한 확인
SELECT grantee, privilege_type 
FROM information_schema.role_table_grants 
WHERE table_name = 'table_name';

-- 특정 사용자의 모든 테이블 권한 확인
SELECT table_schema, table_name, privilege_type
FROM information_schema.role_table_grants
WHERE grantee = 'user_name';
```

### 4.2. 소유자 확인
```sql
-- 테이블 소유자 확인
SELECT tablename, tableowner 
FROM pg_tables 
WHERE schemaname = 'schema_name';

-- 인덱스 소유자 확인
SELECT schemaname, tablename, indexname, tablespace 
FROM pg_indexes 
WHERE schemaname = 'schema_name';
```

## 5. 주의사항
- 권한 변경은 데이터베이스 슈퍼유저나 해당 객체의 소유자만 수행할 수 있습니다
- 소유자 변경 시 새로운 소유자는 해당 데이터베이스에 존재하는 사용자여야 합니다
- 권한 변경 시 기존 프로세스나 애플리케이션의 동작에 영향이 없는지 확인해야 합니다
- 권한 변경 전 반드시 백업을 수행하는 것이 좋습니다

## 6. 인덱스 소유자 관련 추가 정보

### 6.1. 인덱스 소유자 특징
- 인덱스는 기본적으로 해당 테이블의 소유자가 소유합니다
- 테이블 소유자를 변경하면 해당 테이블의 인덱스 소유자도 자동으로 변경됩니다
- 인덱스는 독립적으로 권한을 부여할 수 없습니다 (테이블 권한에 종속됨)

### 6.2. 인덱스 소유자 확인
```sql
-- 특정 인덱스의 소유자 확인
SELECT 
    schemaname,
    tablename,
    indexname,
    pg_get_userbyid(idx.indexrelid::regclass::oid) as index_owner
FROM 
    pg_indexes idx
WHERE 
    indexname = 'index_name';

-- 특정 스키마의 모든 인덱스 소유자 확인
SELECT 
    schemaname,
    tablename,
    indexname,
    pg_get_userbyid(idx.indexrelid::regclass::oid) as index_owner
FROM 
    pg_indexes idx
WHERE 
    schemaname = 'schema_name'
ORDER BY 
    tablename, indexname;
```

### 6.3. 주의사항
- 인덱스 소유자를 직접 변경하는 것보다 테이블 소유자를 변경하는 것이 권장됩니다
- 인덱스 관련 작업(생성, 삭제 등)은 테이블 소유자 권한이 필요합니다
- 인덱스 소유자 변경 시 해당 인덱스의 유지보수 책임도 함께 이전됩니다

## 7. PostgreSQL 13 버전 관련 참고사항

### 7.1. 버전 특이사항
- PostgreSQL 13에서도 모든 위의 명령어와 기능이 동일하게 동작합니다
- `ALTER INDEX` 명령어는 PostgreSQL 9.2 버전부터 도입되어 13 버전에서도 계속 지원됩니다
- 인덱스 소유권은 여전히 테이블 소유권과 연결되어 있습니다

### 7.2. 권장되는 추가 보안 설정 (13 버전)
```sql
-- 스키마 검색 경로 설정 확인
SHOW search_path;

-- 안전한 검색 경로 설정
ALTER ROLE user_name SET search_path = "$user", public;

-- 객체 권한 감사 활성화 (로깅)
ALTER SYSTEM SET log_statement = 'ddl';
ALTER SYSTEM SET log_line_prefix = '%t [%p]: [%l-1] user=%u,db=%d,app=%a,client=%h ';
```

### 7.3. 권한 관리 모범 사례 (13 버전)
- ROLE을 사용한 권한 관리 권장
- 최소 권한 원칙 적용
- 정기적인 권한 감사 수행
- PUBLIC 스키마에 대한 기본 권한 제한

### 7.4. 알려진 제한사항
- 인덱스에 대한 개별 권한 부여는 불가능 (테이블 권한에 종속)
- 테이블 소유자 변경 시 관련된 모든 객체(시퀀스, 인덱스 등)의 소유권도 함께 변경됨

## 8. Sequence 소유자 및 권한 관리

### 8.1. Sequence 소유자 변경
```sql
-- 단일 시퀀스 소유자 변경
ALTER SEQUENCE sequence_name OWNER TO new_owner;

-- 특정 스키마의 모든 시퀀스 소유자 변경
DO $$
DECLARE
    r record;
BEGIN
    FOR r IN SELECT sequence_name 
            FROM information_schema.sequences 
            WHERE sequence_schema = 'schema_name'
    LOOP
        EXECUTE 'ALTER SEQUENCE schema_name.' || quote_ident(r.sequence_name) || ' OWNER TO new_owner';
    END LOOP;
END $$;
```

### 8.2. Sequence 권한 관리
```sql
-- 시퀀스에 대한 모든 권한 부여
GRANT ALL PRIVILEGES ON SEQUENCE sequence_name TO user_name;

-- 특정 권한만 부여 (USAGE: 시퀀스 사용, SELECT: 현재 값 조회, UPDATE: 시퀀스 수정)
GRANT USAGE, SELECT ON SEQUENCE sequence_name TO user_name;

-- 스키마의 모든 시퀀스에 대한 권한 부여
GRANT ALL PRIVILEGES ON ALL SEQUENCES IN SCHEMA schema_name TO user_name;

-- 향후 생성될 시퀀스에 대한 권한 설정
ALTER DEFAULT PRIVILEGES IN SCHEMA schema_name
GRANT USAGE, SELECT ON SEQUENCES TO user_name;
```

### 8.3. Sequence 정보 확인
```sql
-- 시퀀스 소유자 확인
SELECT 
    sequence_schema,
    sequence_name,
    pg_get_userbyid(c.relowner) as sequence_owner
FROM 
    information_schema.sequences s
    JOIN pg_class c ON c.relname = s.sequence_name
WHERE 
    sequence_schema = 'schema_name';

-- 시퀀스 권한 확인
SELECT 
    grantee, privilege_type
FROM 
    information_schema.usage_privileges
WHERE 
    object_type = 'SEQUENCE' 
    AND object_name = 'sequence_name';
```

### 8.4. 주의사항
- 테이블의 SERIAL 컬럼에 연결된 시퀀스는 테이블과 함께 소유자가 변경됩니다
- 시퀀스 소유자 변경 시 해당 시퀀스를 참조하는 테이블의 권한도 확인해야 합니다
- USAGE 권한이 없으면 nextval() 함수를 사용할 수 없습니다
- 시퀀스 변경 전 현재 값과 사용 중인 애플리케이션의 영향을 확인해야 합니다
